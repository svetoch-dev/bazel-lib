# v0.33.0

## Pin the library and `rules_distroless`

Update the downstream `svetoch_bazel_lib` override in `MODULE.bazel` to the
full commit SHA referenced by the `v0.33.0` tag. This release uses
`rules_distroless` v0.11.2. Bzlmod applies overrides from the root module, so
when consuming this release from a downstream workspace, add or update this
override in its root `MODULE.bazel`.

```starlark
bazel_dep(name = "rules_distroless")
git_override(
    module_name = "rules_distroless",
    commit = "cdd138b5931e0919b01ddab5a8957885885c40ce",  # v0.11.2
    remote = "https://github.com/bazel-contrib/rules_distroless",
)
```

## Configure APT signing keys

Add `gpg_keys` to each downstream `apt.sources_list` for a signed repository.
The extension uses these public keyrings to verify APT release metadata.
For Debian sources, including Debian security snapshots, add the bundled
keyring to each source declaration.

```starlark
gpg_keys = [
    "@svetoch_bazel_lib//deps/deb/keys:debian-archive-keyring.gpg",
],
```

For third-party sources, reference the signing keyring published by that
repository's operator. Export the keyring file from its Bazel package so the
extension can read it. Keep the existing source URLs, suites, architectures,
and package selections. Projects that only consume the library's image
targets get the library's Debian source configuration through the dependency.

## Migrate direct `aspect_bazel_lib` usage

Search downstream `MODULE.bazel`, `BUILD.bazel`, and `.bzl` files for
`aspect_bazel_lib`. This release uses `bazel_lib` 3.8.0 and `tar.bzl` 0.10.9.
Declare each module in the downstream root if it uses that module directly.

- Replace `load("@aspect_bazel_lib//lib:tar.bzl", ...)` with
  `load("@tar.bzl", "mtree_mutate", "mtree_spec", "tar")`, keeping only the
  symbols used by the file.
- Use `@bazel_lib//lib:expand_template.bzl` for `expand_template`.
- If the workspace imports `zstd_toolchains`, switch its `toolchains`
  extension to `@bazel_lib//lib:extensions.bzl` and retain the existing
  `use_repo(..., "zstd_toolchains")` declaration. This includes workspaces
  that call the library's `deb_packages` macro in their own BUILD files.
- Remove the direct `aspect_bazel_lib` dependency after migrating its remaining
  usages. It can still appear in `MODULE.bazel.lock` through dependencies
  such as `rules_oci`, `rules_distroless`, and `rules_tf`.

## Verify image layers and the lockfile

Several library image layers and the interpreter, packages, and application
layers from the `rules_python` path of `py_layers` now use gzip compression.
Audit consumers that read layer files directly, especially scripts that assume
an uncompressed tar or refer to a generated filename. Check custom
`mtree_mutate` destinations for trailing slashes in `package_dir`. Use paths
without trailing slashes and inspect the rebuilt archives for the expected
entries.

Build the affected image targets and run `bazel test //...` from the downstream
repository root. Let Bazel regenerate `MODULE.bazel.lock` and include the
lockfile with the module and signing-key changes.
